Each component is authoritative for its declared fields; a copy that lacks any component is not the register. `register/pending/` and any generated reading view are not authority. Every other copy — the provider projects, any attachment in circulation — is a read-only mirror, refreshed by copy, never edited in place; a mirror that disagrees with it is stale by definition. **Authority transferred to that path on commit `5446e6e` (2026-09-17).** After that commit, allocations, status changes and protocol amendments take effect only when merged to canonical `main`; branches and pull requests are proposals.

**Scope: the play-well cluster, not one repo.** This register governs correspondence for `ojfbot/lego-village-pipeline` and `ojfbot/play-well-library` together, and any further play-well repo. It may later move to a repo of its own. **Moving the register's home is a copy plus an authority transfer recorded here — it never re-keys anything**: numbers, prefixes, revisions and citations are independent of where the register lives.

**Register version: 2026-09-18.33** — one register version per accepted landing transaction, assigned only at finalization against protected `main` by `tools/register_finalize.py` (Q-02/Q-03, HANDOFF-LEGO-PIPE-032-R1); never claimed on a branch, never bumped by hand. Single monotonic register across threads and providers (instituted 2026-09-17, CORR-LEGO-PIPE-013 finding N-01). Type prefixes: `HANDOFF-` (work orders and design packages), `CORR-` (reconciliation and reply memos), `REVIEW-` (independent reviews). Revisions `R0, R1…` do not consume numbers. Historical collisions are kept, never silently renumbered.

**Rules in force**

1. **James allocates** numbers or explicitly delegates an allocation. No agent infers a free number from a mirror.
2. **Allocation is recorded as reserved before drafting.** Reservations consume numbers and are never recycled.
3. **A number is never reused or moved after a memo reaches an agent.**
4. **Collisions are recorded, not silently repaired.** Prefix disambiguates different types; prefix + number + thread disambiguates same-prefix collisions.
5. **Canonical citation is prefix + number + revision.** Historical unprefixed files remain byte-frozen and receive a prefixed citation form in the register.
6. **Revision** preserves author, recipients, authority, purpose and scope. Supersession by a different memo is not renumbering.
7. **A new number** is required for a reply, review, decision, work authorization, changed recipients, changed authority or materially changed scope.
8. **Revisions consume no numbers.**
9. **Issuance** requires operator authorization or delegated authority, a frozen revision, successful preflight, canonical registration and verifiable transfer.
10. **Only an issued memo can be superseded**, and both rows record the relationship.
11. **Transfer exposes verifiable bytes.** Use file attachment when the recipient lacks repository access. For a recipient with canonical-repository access, repository + path + commit SHA + content SHA-256 is equivalent. Paste is never transfer.
12. **Failed preflight cannot create an operative work order.** Repair the same revision while unissued; after issuance, repair by revision.
13. **One register holds authority:** this file on canonical `main`. Mirrors are read-only. Moving the register requires a recorded authority transfer and never re-keys history.
14. **Schema version is per memo; operative status is register data.** Ratification and validator capability are separate. During the `.13` migration, v1 remains accepted for legacy and transition material; v2 governs new memos, but no v2 work order acts until a v2-aware validator passes it.
15. **Filename is not identity.** The row records canonical path, aliases, schema and transferred SHA-256.
16. **Thread names are register data**, not a hardcoded validator enum. Current names: `design`, `build-harness`, `correspondence-governance`, `cluster`, `drafting-table`.
    Note (`.22`): `drafting-table` is the whole planner — adapters to schema to UI — by operator ruling 2026-09-18; it replaces the proposed `app-stack`, which was never confirmed and survives only on the 023-R0/R1 rows as recorded.
17. **ChatGPT contributions are PR-only.** ChatGPT may create branches, commits and draft PRs but never writes directly to `main`. By the `.21` ruling, Codex (the ChatGPT desktop agent) holds the same relayed-landings self-merge lane as Claude Code — self-merge only of PRs whose content the operator authorized by relay (file landings, instructed register bumps), never code, schema, or policy. A contributing steward includes its memo and proposed register delta in one reviewable PR; every other merge to canonical `main` is serialized by James.
18. **Merge-method enforcement:** canonical `main` accepts only merge commits; `register-lint.yml`'s settings check fails a PR that finds squash or rebase merging enabled. Ratified 2026-09-20 (PR #21 decision docket, Q-06; James disables squash and rebase merging repository-wide, retains merge commits, does not require linear history); lands with the HANDOFF-LEGO-PIPE-032-R1 migration, register read `2026-09-18.31`. RL-18 is a ratchet: once this rule is on `main`, its removal or alteration is an error unless the same commit adds an explicitly numbered successor rule that names Rule 18 as superseded — never a deletion, never an anomaly entry.
