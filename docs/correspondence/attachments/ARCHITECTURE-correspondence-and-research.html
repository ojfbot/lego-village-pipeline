Correspondence and research — how the agents leave each other documents

Drawn 2026-09-18 · describes, decides nothing

Six parties that cannot convene. Two classes of document — speech acts with a number, knowledge with a hash. One register under git that is the only authority. One validator that knows v1 while v2 is ratified. Five venues, and only two of them can write to the record.

1 Two classes, two pass-throughs

A correspondence document asks or tells someone to do something, so it needs a number that never moves. A research document says what is known, so it needs a hash and a verification tag on every claim.

2 What a number is

Identity is prefix + number + revision. It is not the filename, not what the file's own frontmatter claims, and it is not repaired when it collides.

3 The lifecycle

Issuance is the gate: authorization · frozen revision · passing preflight · register row · verifiable transfer. Before it, repair the same revision; after it, only a new revision or a new number.

4 Venues, and who can write to the record

Transfer is by attachment with a hash, or repository-native for anyone with repo access. Paste is never transfer. Only two agents commit; only James merges.

5 v1 operative, v2 ratified — one validator that knows v1

Ratification is a decision James makes; validator capability is code Claude Code writes. Separating them (X-04) is what lets the protocol move without pretending the tooling exists.
