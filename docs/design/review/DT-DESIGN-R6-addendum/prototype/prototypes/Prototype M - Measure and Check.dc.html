PROTOTYPE ASSUMPTIONS
  • Two control loops (014 §3.3): capture a measurement and verify a claim. Both must return the user to the interrupted work — the YOU CAME FROM bar reads ?from= and carries a return link; on a real sheet it restores scroll and selection.
  • A measurement is a new field revision with tool, unit, author and time; the old value is kept and struck through, never edited. schema_request: Measurement { subject, field, value_ldu, display_unit, tool, by, at, supersedes, evidence_ref } (014 §7.8).
  • Tree values below are the operator’s 2026-09-17 measurements (DEC-016). Values are entered in the unit the tape gives; stored as integer LDU (014 §7.1).
  • Verified claims carry method + evidence; AI stance is never authority (014 §8). “Can’t check yet” parks with an owner and due trigger.
  • Photo attachment is real in the prototype — the picker takes one or more files from the device, each becomes a chip with thumbnail and filename, and the filenames ride along on the recorded value. Nothing is uploaded; the overlay/measure-from-photo step is still mocked. Blast-radius list is mocked from a fixed dependency map.
  • A measurement can have more than one axis: the tree base is recorded as width × depth × height in one commit, so the fit check never gets two of three. Single-axis rows are unchanged.
  • Every recording is signed: the confirm block asks for initials (e.g. jfo) and “Yes, record it” stays disabled until they’re typed — authorship is part of the value, not metadata added later.
  • SetRef (operator ask 2026-09-17): every set / MOC / part number is a hover-or-focus reference card — image, name, the facts we hold, BrickLink + Rebrickable links. Reference comes from BrickLink, never LEGO.com. Drop the set image onto the card once; it persists.
