MOCK DATA · SCHEMA REQUESTS
  • All quantities, part ids, colours and prices are design mocks — real values need Claude Code implementation plus independent agent audit
  • Basis is split (014 §7.2). Stored on the row: acquisition · transformation · epistemic_state · disposition. Derived from the parent Design / Request: need_origin · design_origin. The chip on each row is composed from these — users never meet the enums; expand a row → "the six axes" to see the plumbing. A row is a demand; it never becomes "received" (§7.3). Filters read axes, not the old basis enum.
  • Vendor is per asset (LEGO direct vs BrickLink) and drives every link. schema_request: Asset {vendor, product_url}
  • Options carry worked-out state {modeled, fit_checked, stances[]}. schema_request: Option {modeled_ref, fit_ref, stances}
  • Plans are open by default; anyone in the village — or their helper — can attach a Request to someone else's plan. schema_request: Plan {owner, open, attached_requests[]}; Request {on_behalf_of, via_agent, attached_to_plan}
  • Requests carry attached work {model_ref, fit_ref} so "words only" is visible. schema_request: Request {attached_work[]}
  • Prices are low–high across available BrickLink lots. Vendor-smart ordering → P-01
