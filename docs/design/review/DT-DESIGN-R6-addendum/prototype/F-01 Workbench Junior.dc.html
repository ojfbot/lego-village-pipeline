HOW THIS SHARES TOOLS WITH JAMES’S SHEETS
Three things, kept apart: a sticker says what the idea is; its envelope is the room it claims — a footprint in studs plus the height that is actually clear there (under the branches, less); a model (step 4) is something that must fit inside that envelope. Same tokens, same request card, same basis (story), same evidence chips — at lower density, bigger targets, plain words. A sticker is a layout-branch proposal that claims an envelope; "Send to James" is exactly the @boys request that C-01 answers, with attached work listed so "words only" is visible. The tree’s base, height and branch overhang are ◇ TO BE MEASURED (J9) — adjust them in Tweaks; every headroom check follows. The magic wand is a mock — the real one needs a retrieval backend (story + claimed area + kind → precedent study → proposal) and an audit. Private designs are filtered out before this page ever renders them. Every sticker carries its own story (who or what it is, what it does here) beside the scene’s story — both travel on the request (schema: Sticker {label, story} → story-graph node, J11). Envelopes are capped at 32 × 32 studs — one MILS module — for now. Naming open: “Rail” on the SHOW row is a placeholder for a namespace still to settle — rail · railbed · right-of-way (the studs the train needs clear beside it) · rail infrastructure (stops, signals). No step here can buy, freeze, or change James’s layout.
