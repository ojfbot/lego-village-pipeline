# Give the dashboard its space

## Required direction

The current side sheet is insufficient. The operator requests a near-full-screen dashboard modal with a ghosted view of the house behind it. The dashboard receives the real estate established by the Claude handoff. The house supplies context around the threshold, not a permanently occupied half of the working area.

This is **intent, not an implemented modal in R0**. `overview.html` is a labeled concept illustration. The running prototype still uses its earlier side sheet.

## Layout to prototype

- On desktop, try a sheet inset by about 24px on all sides. This is a starting visual target, not an accepted spacing token. Use almost the whole viewport for dashboard content.
- Freeze the house at the entry bookmark, reduce its contrast behind the modal, and leave it discernible around the sheet. Compare a plain scrim with very light blur. Do not animate or continuously render a background that the person cannot operate.
- Let the existing page determine its internal skeleton. A-01 needs canvas and exact controls; B-01 needs an answer-focused column; inventory needs ruled records; a review gate needs its own quiet confirmation. Do not turn every page into an identical dashboard card grid.
- Preserve the Drafting Table token contract, page title, primary act, source identity and threshold context. Bubble font is appropriate for accent titles; it is not the typography for a dense parts table or provenance record.
- Keep the full desktop dashboard columns when space permits. Collapse based on the dashboard's container, not the width of an artificial half-screen side panel.
- On small screens, the dashboard can occupy the viewport. Respect the handoff's phone scope and input/target guidance rather than promising a usable precision canvas on every phone.

## Queue, trail, footer and Benny

The R4 Workbench Frame is a wireframe demonstrating optional capabilities. Queue, Trail and Ledger are not bars that every page must receive, and the bars do not all share one visual chrome. Its nested subgrid and container-query intentions require technical design before implementation.

Benny remains visibly AI-originated. His panel may reveal a question or route to another sheet; it must not silently change work. Respect the source's push-the-board intent when sufficient dashboard space is available. Prototype a small-screen presentation separately. Do not settle durable ledger ownership, shared-store topology or agent permissions through a visual sidebar.

The typology specimen uses form and layout to distinguish page acts. Preserve that inquiry when restoring dashboard space. A selectable room is an entry point, not proof that its page has one exclusive kind.

## Dialog and state contract

- Use one labeled modal dialog and retain one document H1. Inert the scene and header surfaces that are behind the modal.
- Move focus to the page title or meaningful starting control, contain keyboard focus, expose a named close control and announce the page change.
- On close, return to the exact connected activating control or a clear fallback. Restore the scene bookmark without a surprise flight.
- Keep form drafts and nested page navigation state. Opening another sheet must not erase prior input or treat navigation as approval.
- Separate a work-change confirmation from the page modal. Announce an AI proposal and restate its change before a save, according to existing project rules.
- Animate only the sheet threshold and intentional elements. Do not use document-level snapshots for hover, local card state, acknowledgement or a Benny response.
- Test browser history, Escape from nested dialogs, text enlargement and long page titles. The poem's preferred one-line presentation never authorizes truncating essential work text.

## Evidence from the source handoff

The R4 limitation note records whole-page flashing when local state changes, driven by whole-board re-rendering and document View Transitions. Its suggested component state, selectors, element transitions, CSS Grid, subgrid and container queries are starting points for a technical session, not a settled architecture.

The inherited responsive document explicitly calls its layouts intent and says small-device design is unfinished. A-01's spec requires a linked viewer and canvas, exact entry, semantic layers and retained proposals. Restore this working space; do not claim that R0's small mock ring diagram implements those capabilities.
