# docs/design/ — design-package cuts

Home of every design package Claude Design exports: the verbatim trees, their importer
records, and the tooling contract. Governed by **HANDOFF-LEGO-PIPE-024-R1** (the
design-package protocol, reconciled through REVIEW-025-R1 / REVIEW-026 and the PR #12
disposition). The correspondence register's **instruments table** is the registration
authority; this README is the working guide.

## Identity: the cut key

A cut is identified by **`{design_package, revision, cut_state}`** — uniqueness is
enforced on the triple, and a pin naming only package and revision is a **validator
error**, never a silent choice (operator ruling 2026-09-19, register `.24`).
`cut_state` is an immutable part of identity — *not* lifecycle status. Vocabulary
(register data, like thread names): `as-exported` (a fresh designer cut) ·
`as-reviewed` · `as-committed`. A second received state under one package+revision gets
a new durable `cut_state`; an existing key never changes. Every received state stays
addressable.

**The directory name is never identity; the manifest is** (register rule 15 applied to
packages). Nothing may parse `-R(\d+)$` out of a directory name. A pin resolves through
the instruments table to one `package_path` and one immutable `tree_sha256`. The package
label is **`DT-DESIGN` from cut R2**; existing `H-01-*` names never move, and **no alias
redirects `H-01` pins to `DT-DESIGN`.**

**Qualified pin grammar** (supersedes the bare `design_pin: H-01 R<n>` form in 023-R2's
prose): a booklet pins `design_pin: {design_package: H-01, revision: R1, cut_state:
as-committed}`. Bags 1–3 pin exactly that cut. Check a booklet with
`python3 tools/design_pkg.py pin <booklet.md> docs/correspondence/REGISTER.md` — bare,
ambiguous and unregistered pins all exit 1.

**A new cut state is coined in the register, never in a manifest.** The declared list
lives beside the instruments table (`Current cut states:`), read at run time like rule
16's thread names. An undeclared state warns; an undeclared state with no matching row
is an error, because that combination is indistinguishable from a typo that would both
invent an identity and skip the digest check protecting it.

## Two authors, three record types

| File | Author | Schema | Where |
|---|---|---|---|
| `package.yaml` | Claude Design, inside the exported archive | `design-package/v1` | at the package root, inside the verbatim bytes (from cut R2) |
| `<dir>.import.yaml` | the importing agent | `design-package-import/v1` | `manifests/` |
| `<dir>.overlay.yaml` | the importing agent, historical cuts only | `design-package-overlay/v1` | `manifests/` |

Schemas live in `tools/schemas/`. A reconstruction overlay is **not** a manifest — the
designer cannot retro-sign bytes it did not export; overlays are bound to
`{package_path, tree_sha256}` and carry per-field evidence strength. A file claiming
`manifest_origin: designer` found in `manifests/` is an error.

**Verbatim rule:** package directories hold exactly the received bytes.
`diff -r <received> <committed>` is empty, with no exclusion list — which is why every
importer file lives in `manifests/`, never inside a package directory.
Deterministic names: `<dir>.import.yaml` · `<dir>.overlay.yaml` ·
`drift-<old-dir>-to-<new-dir>.md`.

## Tools

```sh
python3 tests/test_design_package.py            # the acceptance battery — run this first
python3 tools/package_preflight.py PACKAGE_DIR docs/correspondence/REGISTER.md \
        [--overlay manifests/<dir>.overlay.yaml] [--import-record …] [--previous PREV_DIR]
python3 tools/package_drift.py OLD_DIR NEW_DIR --out docs/design/manifests/drift-<old>-to-<new>.md
python3 tools/design_pkg.py digest DIR          # the normative tree_sha256
python3 tools/design_pkg.py pin BOOKLET.md docs/correspondence/REGISTER.md
python3 tools/design_pkg.py inventory docs/design --write
python3 tools/design_pkg.py kit-mirror [--write]   # keep the kit's schema copy honest
```

`tests/test_design_package.py` is the enforcement record: every claim this directory
makes is a case there, runnable from a clean checkout in one command. A claim without a
case in it is a claim about one afternoon, not a property of the tools.

Every preflight line names its evidence method (`structural_check` · `measured` ·
`declared` · `unattributed` · `unavailable`). The tool checks structure only; runtime
facts (contrast, CDN fetches, landmarks, `file://`) are **declared** observations citing
their source — never verified claims. Drift reports claim **file-level change evidence**,
not semantic drift, until the package carries stable state/schema-request ids. The
decisions ledger is compared by stable `DEC-nnn` id under its header-declared
(newest-first) order — never byte position — with exactly one permitted prior-row
transition: a Status cell gaining a supersession reference naming a new, higher id.

A defect **names a failure**; a waiver **names authority** (who authorized import despite
it, when, under which memo). Missing/mismatched identity, digest mismatch, package-root
escape and a missing manifest are never designer-waivable. `mock_math` is a required
boolean; preflight warns loudly while it is true, and flipping it needs a recorded
operator ruling.

## Import checklist (one PR per cut — a Friday landing)

1. **Verify receipt**: relayed archive hash if one exists (`shasum -a 256`); unzip to a
   scratch location. Record what you received.
2. **Scratch preflight**: `package_preflight.py <scratch> REGISTER.md` (designer cuts
   need `package.yaml` inside; a manifest-less cut goes to step 8).
3. **Branch** from freshly-merged `main` (`corr/design-import-<dir>`); re-verify branch
   state first — the clones are shared by concurrent agents.
4. **Land verbatim**: copy the tree to `docs/design/<dir>/`; prove `diff -r` empty;
   `design_pkg.py digest` the committed tree.
5. **Write the import record** (`manifests/<dir>.import.yaml`), rerun preflight with
   `--import-record` (digest must verify), run `package_drift.py <previous> <new> --out
   manifests/drift-….md`.
6. **Register, same commit**: bump the version line, add the instruments row,
   regenerate this README's inventory (`design_pkg.py inventory docs/design --write`).
   **Renumber-on-rebase is ordinary procedure** (025 R-25): if another PR takes your
   register version while you're in flight, renumber to the next free and note it.
7. **PR + merge per the ratified lane** (below).
8. **A failed or manifest-less Friday still lands its record**: disposition `rejected`
   or `recorded_not_imported`, an instruments row with that Status, no bytes; the
   previous pin does not move. Friday never disappears from the record.

## Merge authority (import-lane boundary, ratified 2026-09-19)

- **Interpretation is operator-merged**: reconstruction overlays, historical drift
  reports, anything requiring provenance/waiver/historical judgment — and, as always,
  schema, tools and protocol.
- **The mechanical lane** (relayed-landings self-merge, register `.14`/`.21`) covers a
  future operator-relayed cut's deterministic products — verbatim bytes, the register
  version bump, the instruments row, machine-generated receipts and drift output — only
  once the schema makes those products judgment-free. An import record is transcription
  and may ride the lane; a reconstruction is interpretation and may not.
- The historical landings (H-01-R0, H-01-R1-reviewed, H-01-R1 records) are James-merged.

## Authority pointers

This README explains; it decides nothing. Authority order: the operator's rulings →
`docs/correspondence/REGISTER.md` (rows, instruments table, version notes) →
HANDOFF-LEGO-PIPE-024-R1 → 023-R2 §5 (pin · cut · drift · change request) → the schemas.
Build authority comes **only** from a booklet's pin — never from `maturity`,
`tier_coverage`, or anything in this directory.
